# Pre-registered V2: generator of a proof-critic inference schema

Date: 2026-10-11. Parent: independently qualified V1 at MSI `660ab9a006aafacf0ed4e8bfb2f51a26124c342f` (CI 38089943007). No external outreach, merges or publication claims.

## Research question
Can a typed, verified failure establish that the **unbounded** old equality-chain critic is inadequate, induce a **new general inference schema** rather than select a named `repeat` operation, and reuse it on independently frozen equations involving unfamiliar function symbols and nested contexts?

## Source and scope
Finite first-order terms built from atoms and unary uninterpreted function symbols. Statements are equality goals under a finite conjunction of asserted equalities. Old C0 knows source equality edges, symmetry, reflexivity, and **unbounded** transitive chaining between explicitly occurring whole terms. It has no congruence/context-construction rule. Absence of an old C0 path is a complete obstruction ONLY in that old grammar; it is not an assertion about Lean or Bundy's critics.

## Lower substrate and verification
The lower substrate has term parsing/constructors, metavariable binding, independently checked Boolean models for candidate universal rules, and a *generic* external proof authority (Lean's equality eliminator). The inventor must derive a candidate rule **as a first-order schema over source symbols**, not receive a named proof critic `repeat`, a target-specific function name, or a pre-selected theorem name. Generated proof steps must be source-bound and separately checked in Lean 4.24; Python tests cannot promote their own soundness.

## Frozen development and unseen transfer
Development provides two distinct proof obstructions: one application of a unary constructor to both sides of an equality, and a nested application involving transitive composition. It also includes a bad differing-constructor case and an ungrounded case. The held-out module is imported ONLY AFTER the final induced rule bytes/hash are fixed. Its functions and terms are independent of development labels. It contains distinct functional contexts, mixed premises, extra/irrelevant source evidence, missing premises, mismatched-head counterexamples, and protected old-C0 consequences.

## Controls
1. Prove old C0 completeness through actual graph component closure, NOT depth limits.
2. Independently check rule-schema universal semantic soundness for every Boolean valuation and function interpretation, and reject asymmetric-head forged rules.
3. Source-bind each derived proof and compile real Lean terms (no `sorry`, `admit` or unsound `axiom`).
4. Remove rule and necessary premise separately; remove irrelevant evidence as non-interference control.
5. Compare a fully equipped stateless congruence-closure solver, and an executable-memory replay comparator, with identical protected task access. Do not claim unique advantage if they tie.
6. Independently hash and freeze rule before importing heldout. Charge candidate rule attempts, semantic validator calls, old search, checking and replay. Total lifecycle advantage cannot be claimed from incomplete accounting.

## Promotion / rejection
**WARRANTED_BOUNDED_SCHEMA_GENESIS** requires the old complete C0 to be inadequate, an induced generic schematic rule absent from old C0, kernel accepted generated proof terms on unseen frozen tasks, conservative negatives and causal ablations, with source-exact CI and corpus hashes. **STRONG_BREAKTHROUGH** additionally requires a protected gain beyond matched full-language stateless / executable-memory controls, or a new constructor grammar not anticipated by the lower supplied interpreter, plus independent naturally authored transfer. If those do not land, report NEGATIVE for that stronger claim, not UNKNOWN presented as a success.
